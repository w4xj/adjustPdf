# 数字签名和电子印章风险说明

## 1. 为什么处理旋转会影响签名

PDF 数字签名会对文件中特定字节范围进行摘要和签名，典型结构包括：

```text
/FT /Sig
/V
/Type /Sig
/ByteRange
/Contents
```

旋转固化会重新写入页面内容、页面边界、对象和交叉引用结构。因此，即使页面肉眼显示效果不变，新生成文件的字节内容也已经改变，原有签名验证会失效。

程序始终生成新文件，不覆盖原文件；正式验签、归档和提交时必须保留并使用原始签章文件。

## 2. 主界面提示

主界面长期显示：

> 重要提示：本工具会重新写入 PDF 页面内容，仅建议用于未加盖电子印章、未进行数字签名的文件。处理已签章或已签名的 PDF，会导致新生成文件的签名验证失效。程序不会覆盖原文件，请务必保留原始签章文件。

## 3. 开始处理前的预检

点击“开始处理”后，程序会在写出任何文件之前检查全部待处理 PDF。

```text
未检测到数字签名
  → 正常处理

检测到数字签名
  → 显示风险确认窗口
  → 默认取消处理
  → 用户明确确认后才继续

文件无法完成签名预检
  → 整批文件都不处理
```

确认窗口按钮：

```text
取消处理
我已了解风险，仍然继续
```

按 Enter、Esc 或关闭窗口都按取消处理。

## 4. 可以检测的标准结构

程序可以区分：

### 空签名字段

```text
/FT /Sig
但没有有效 /V、/ByteRange、/Contents
```

这种情况通常只是预留签名框，不判定为已经签署。

### 已写入数字签名

```text
/FT /Sig
/V 指向签名字典
/ByteRange 存在
/Contents 非空
```

这种情况判定为检测到标准 PDF 数字签名或电子签章结构。

程序也会检查 Catalog 的 `/Perms /DocMDP` 文档认证签名。

## 5. 检测的限制

本工具只检测签名结构，不进行密码学验签，因此不能判断：

- 证书是否可信；
- 证书是否过期或吊销；
- 签名是否具有法律效力；
- 时间戳是否可信；
- 证书链是否完整。

仅有扫描红章、图片印章、`/Subtype /Stamp` 批注或厂商自定义格式时，可能无法判定为标准数字签名。

## 6. 命令行安全策略

命令行模式默认拒绝处理已签名 PDF：

```powershell
.\.venv\Scripts\python.exe -m adjust_pdf --cli signed.pdf
```

如果已经确认风险，必须显式添加：

```powershell
.\.venv\Scripts\python.exe -m adjust_pdf --cli signed.pdf --allow-signed
```

